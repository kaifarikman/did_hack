# AGENTS.md

## Контекст

1. Перед началом работы прочитай `context/README.md`, затем нужные файлы по его указателю.
2. Требования организаторов и предложения команды храни в разных файлах.
3. Изменилась договорённость — обнови файл в `context/` и статус в `context/README.md`.
4. Утверждённые решения помечай явно. Открытые вопросы не удаляй, пока на них не ответили.

## Код

1. Соблюдай чистую архитектуру: бизнес-логика не импортирует фреймворки, БД и транспорт.
2. Одна функция, класс или модуль отвечает за одну задачу.
3. Называй сущности по смыслу. Не используй `data`, `tmp`, `res`, `x` и непонятные сокращения.

## Тесты

1. Покрывай тестами новую логику.
2. Не запускай тесты перед каждым пушем. Запускай, если менял критичную логику или делал рискованный рефакторинг.

## Коммиты

1. Не добавляй `Co-Authored-By`, `Generated with` и любые упоминания ИИ в коммиты и PR.
2. Заголовок коммита — одна строка до 50 символов.
