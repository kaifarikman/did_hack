# Требования и оценивание

Источник: [ТЗ](../task/2-Описание%20задачи.pdf), с. 1–5. Здесь пересказ требований организаторов; идеи команды находятся в [approach.md](approach.md).

## Задача и среда — с. 1–2

- Агент самостоятельно ставит физические эксперименты, управляет роботом, анализирует результаты и адаптируется.
- Цель: собрать как можно больше скрытых образцов и вернуться на базу, изучая местоположение образцов и дорогие участки пола. Батарея ограничена; решения нужно объяснять.
- Используются ROS 2 Jazzy, Gazebo Sim Harmonic, TurtleBot3 Burger и `turtlebot3_world` из официальных пакетов. Арена шестиугольная, с девятью столбами.
- Робот и мир указаны как «без изменений». Одновременно требуется генератор сценариев с грунтами, событиями и прочим; команде разрешено сгенерировать свою карту. Допустимые границы изменений требуют уточнения.
- Начальные координаты, карта и ROS-контракт вынесены в [interfaces.md](interfaces.md).
- Изменения грунтов, появление опасной зоны и сбой датчика агенту не объявляются. Он обнаруживает их по расходу батареи, штрафам и поведению датчика.
- В опасных зонах возможны поломки и отказы на выбор команды.

## Сценарии — с. 2

| Сценарий | Образцов | Грунтовых зон с медленной проходимостью | Изменения во время прогона |
| --- | ---: | ---: | --- |
| easy | 3 | 1 | Нет |
| medium | 5 | 3 | Нет |
| hard | 7 | 4 | Смена грунтов, новая опасная зона, сбой датчика |

ТЗ описывает грунты и через стоимость движения, и через медленную проходимость. Конкретная физическая модель не дана.

## Уровни решения — с. 2–3

| Уровень | Обязательное поведение | Проверяемый результат по смыслу ТЗ |
| --- | --- | --- |
| 0. Среда | Установить пакеты, запустить мир, teleop_keyboard и судью; посмотреть топики через `ros2 topic echo` | Идут `/odom`, `/scan`, `/did/battery`, `/did/sample_sensor`; батарея убывает при езде |
| 1. Навигация | Планировать на сетке со стоимостями; запретить стены и запас вокруг них; превратить путь в путевые точки; публиковать `TwistStamped` | Робот доезжает до цели; разрешён готовый планировщик Nav2 |
| 2. LLM | По текстовой миссии и состоянию формировать список подцелей: исследовать, подойти, собрать, вернуться | Подцели исполняются алгоритмом; LLM работает только на верхнем уровне, вне контура скорости |
| 3. Научный цикл | Искать образцы по сигналу датчика; оценивать стоимость грунта по расходу батареи на единицу пути; вести журнал гипотез и экспериментов | Гипотеза проверяется действием, результат меняет карту стоимостей и решения |
| 4. Адаптация | В hard замечать расхождение прогноза с наблюдением: расход, штрафы, шум датчика | Агент пересматривает модель и перепланирует маршрут |

Для поиска в ТЗ приведены примеры: поиск максимума, спираль, градиентный подъём. Конкретный алгоритм не закреплён. Разрешена любая доступная LLM; примеры — QWEN и DeepSeek.

## Критерии жюри — с. 3–4

| Критерий | Вес | Что показать |
| --- | ---: | --- |
| Работоспособность | 30% | Уверенное взаимодействие со средой и поиск образцов |
| Адаптивность | 25% | Генерация сценариев и поведение при изменении среды |
| LLM-планирование и промпты | 15% | Корректные подцели, структура промптов, обработка ошибок модели |
| Научный подход | 15% | Журнал, проверка гипотез, объяснимость |
| Coding-ассистент и процесс | 5% | Кастомные скиллы, тесты, воспроизводимый запуск одной командой |
| Презентация | 10% | Ясный питч и связь с «ИИ как инфраструктура знаний», применение в науке и образовании |

Эти веса — оценка проекта жюри. Формула игрового счёта `/did/score` в ТЗ отсутствует.

## Тайминг — с. 3

- День 1: первые 45–60 минут — команды, установка и уровень 0; затем уровень 1 после AI-мастер-классов и уровень 2 после advanced-промптинга. Вечером показ базового агента.
- День 2: утром уровни 3–4; после пленарного заседания и лекции — адаптация и подготовка питча.
- Финал: 5 минут демо и 2 минуты вопросов.

## Бонусные треки — с. 3

- Самый содержательный научный журнал гипотез.
- Лучшее использование ассистента: показать ускорение разработки кастомными скиллами.
- Два координирующихся робота.
- SLAM Toolbox вместо готовой карты; начало координат карты должно совпасть с мировым.
- «Команда мечты с AI»: использование LLM при разработке всех решений и демонстрация логов процесса.

## Организация и ресурсы — с. 4–5

Рекомендуемый состав — 3 человека: Back/ROS, ML/LLM, аналитик-исследователь. Мастер-классы идут параллельно; ТЗ предлагает распределить участников по секциям.

| Активность | Вклад по ТЗ |
| --- | --- |
| Создание coding-ассистента | Скиллы для сборки, запуска и отладки ROS/Gazebo, launch-файлы и тесты |
| Платформа ИИ для науки | Модели оценки грунтов по расходу батареи |
| Карьерная игра | Распределение ролей в команде |
| AI-спринт «как писать A*» | Построение исследовательских гипотез |
| Advanced-промптинг | Преобразование миссии и состояния в подцели, объяснение решений |
| Пленарное заседание | Научное и образовательное применение для питча |
| Лекция об адаптивном интеллекте | Обучение на ошибках и адаптация уровня 4 |

Задание связывает работу с Python для анализа данных, матанализом, вероятностью и статистикой, алгоритмами и дискретным анализом, ОС и архитектурой компьютера, ООП.

По ТЗ доступны Сфера.Знания, Сфера.Задачи, Сфера.Код; участники могут получить API-доступ на `ai.mai.ru` к QWEN и DeepSeek v4. GPU «Шелдона» предоставляются по отдельному обоснованному запросу. Фактические доступы команды пока не проверены.
