# Среда и интерфейсы из ТЗ

Источник: [ТЗ](../task/2-Описание%20задачи.pdf), с. 1–2. Ниже контракт задания; соответствие установленным пакетам пока не проверено.

## Робот и карта

| Параметр | Значение |
| --- | --- |
| ROS | ROS 2 Jazzy |
| Симулятор | Gazebo Sim Harmonic |
| Робот | TurtleBot3 Burger |
| Мир | `turtlebot3_gazebo`, `turtlebot3_world.launch.py` |
| Карта | `turtlebot3_navigation2/map/map.yaml` |
| Разрешение карты | 0,05 м |
| Старт робота в мире | `(-2.0, -0.5)`; начальный курс нулевой |
| Стартовая батарея | 60; единицы не указаны |
| Радиус сбора | Образец должен быть ближе 0,30 м |

## Координаты

Образцы, зоны и база заданы в мировой системе Gazebo, совпадающей по ТЗ с системой карты. Задание задаёт преобразование:

```text
x_world = -2.0 + odom.x
y_world = -0.5 + odom.y
```

По ТЗ параметры `x_pose` и `y_pose` при запуске мира должны быть нулевыми. Не следует автоматически трактовать их как абсолютные мировые координаты; семантику нужно проверить на конкретном launch-файле и фактическом `/odom`.

Координаты столбов в PDF записаны неоднозначно: «(±1,1; 0 и ±1,1)» с переносом строки. Геометрию следует сверять с картой и world-файлом, а не восстанавливать по этой строке. Координаты базы явно не приведены; совпадение базы со стартом пока предположение.

## ROS-контракт

Направление указано относительно агента.

| Топик / сервис | Тип в ТЗ | Направление | Смысл |
| --- | --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/msg/TwistStamped` | Публикация | Скорость робота |
| `/scan` | `sensor_msgs/msg/LaserScan` | Подписка | 2D-лидар |
| `/odom`, `/tf`, `/imu`, `/joint_states`, `/clock` | «Стандартные», без точных типов | Получение | Одометрия, преобразования, инерциальные данные, суставы, время симуляции |
| `/did/battery` | `std_msgs/msg/Float32` | Подписка | Остаток батареи |
| `/did/sample_sensor` | `std_msgs/msg/Float32` | Подписка | Шумная близость к ближайшему несобранному образцу, от 0 до 1; без направления |
| `/did/collect` | `std_srvs/srv/Trigger` | Вызов | Попытка сбора; успех при расстоянии меньше 0,30 м |
| `/did/finish` | `std_srvs/srv/Trigger` | Вызов | Завершение миссии, фиксация возврата на базу |
| `/did/score` | `std_msgs/msg/String`, JSON | Подписка | Текущее состояние и счёт; схема не дана |
| `/did/events` | `std_msgs/msg/String`, JSON | Подписка | События `collision`, `false_collect`, `hazard_hit`, `sample_collected`; схема не дана |

В ТЗ `/did/events` назван каналом «только штрафных событий», хотя в перечне есть `sample_collected`. Сохраняем полный перечень; смысл штрафов нужно уточнить.

## Что агенту доступно и что скрыто

Геометрическая карта дана. Образцы нужно искать через скалярный датчик; стоимость грунтов — оценивать по батарее и пройденному пути. Датчик не выдаёт направление на образец. Изменения среды не приходят как явные уведомления.

Внутренняя разметка генератора сценариев и истинные параметры среды не описаны как вход агента. Предложение для честного эксперимента: держать их на стороне судьи и показывать отдельно при анализе прогона. Доступность полей `/did/score` необходимо уточнить.

## Неопределённые параметры

В ТЗ нет частот сообщений, QoS, `frame_id`, JSON-схем, закона датчика, закона расхода батареи, длительности прогона, размеров и стоимости зон, размеров штрафов, точных условий `/did/finish` и reset-протокола. Зависимые решения перечислены в [open-questions.md](open-questions.md).
