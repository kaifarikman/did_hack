## 2. Архитектура

Чистая архитектура из `AGENTS.md` сохраняется: зависимости идут только внутрь. **[утв. проектом]**

```
src/
  domain/         чистые типы и правила, без React и без i18n
  application/    сценарии, порты, состояние экрана
  adapters/       http, fixture
  ui/
    app/          корень, провайдеры, раскладка
    features/     mission, map, research, journal, team, locale-switch
    shared/
      ui/         примитивы: button, card, badge, eyebrow, field, stat
      i18n/       словари и типы
      styles/     токены, reset, global.css
      motion/     usePresence, reduced motion, view transition
```

- Направление импортов в `ui`: `app → features → shared`. Фичи не импортируют друг друга, общее выносится в `shared`. `domain` не импортирует ничего, кроме `domain`; `application` — только `domain`; `adapters` не импортируют `ui`. Проверка — `scripts/checks/layers`. **[предл.]**
- Компонент со стилями живёт в своей папке: `index.tsx` + `styles.module.css`. **[предл.]**
- Экспорт только именованный. Default-экспорт допустим только там, где его требует инструмент (`vite.config.ts`). **[утв. глобально]**
- Пропсы описываются `readonly`-интерфейсом `XxxProps`. **[предл.]**
- Все импорты стоят в начале файла. **[утв. глобально]**
- Повторяющийся визуальный блок становится компонентом в `shared/ui`, а не копией разметки. **[утв.]**

## 3. Тексты и языки

**[утв.]** Два языка, RU и EN. Все тексты интерфейса берутся из словарей, как в rlt. RU — язык по умолчанию.

Устройство (по rlt-hack): **[предл.]**

- `i18next` + `react-i18next`.
- Словари `ui/shared/i18n/locales/{ru,en}/<namespace>.json`. Неймспейсы по фичам: `common`, `mission`, `map`, `research`, `journal`, `team`, `errors`.
- `resources.ts` собирает словари с `satisfies Record<Locale, Record<Namespace, object>>`. `i18next.d.ts` выводит тип ключей из `en`, поэтому опечатка в ключе ломает typecheck.
- Набор ключей в `ru` и `en` одинаков, это проверяет тест.
- `LocaleProvider` хранит выбор в `localStorage` (`did-locale`, чтение в try/catch), выставляет `document.documentElement.lang` и вызывает `i18n.changeLanguage`. Переключатель — фича `locale-switch`, **[утв.]** сделана как в rlt-hack-deploy (`frontend/src/features/locale-switch`):
  - в шапке — квадратная иконочная кнопка с глобусом (`aria-haspopup="menu"`, `aria-expanded`, `aria-label` и `title` = «Язык: Русский»);
  - по клику открывается `Menu` с пунктами `MenuItemRadio` по `LOCALES`: флаг (`Flag`: `ru`, `gb`, SVG 20×15, скругление и тонкая обводка из токенов) + название на своём языке с атрибутом `lang` («Русский», «English») + галочка у выбранного;
  - выбор сразу вызывает `setLocale`, галочка и индикатор выбранного пункта переезжают (`useCheckedIndicator`, только transform), меню закрывается через `settleDelay()` = 220ms (0 при reduced motion), фокус возвращается на кнопку;
  - Esc и клик снаружи закрывают меню; стрелки, Home/End двигают фокус по пунктам;
  - ключи `common:language.{legend,current,ru,en}`;
  - сам текст интерфейса при смене языка меняется сразу, без анимации; анимируются открытие и закрытие меню и индикатор.
- Числа, единицы, время и проценты форматируются через `Intl` по текущей локали (`useFormatters`). Склейки строк из чисел нет.

Модель не хранит готовых фраз (паттерн interrao-hack): **[предл.]**

- `domain` и `application` возвращают ключ сообщения с параметрами (`msg("mission:state.running", { robot })`) или код. Переводит только `ui`.
- Ошибки бросаются как `LocalizedError(key)`, описание ошибки разбирается цепочкой `LocalizedError → errors:api.<code> → errors:kind.<kind>`.
- Перечисления домена (статусы, типы подцелей, исходы гипотез) переводятся через карту `Record<Status, MessageKey>`.

Где допустима кириллица: **[предл.]**

- Кириллица разрешена только в `locales/` и в JSON фикстур, где лежат примеры контракта. Проверка — `scripts/checks/cyrillic`.
- Литеральный текст в JSX и в атрибутах `aria-label`, `title`, `placeholder` запрещён, только `t()`. Проверка — `scripts/checks/jsx-text`.

Контент backend (план LLM, причины решений, тексты гипотез из журнала) — это данные, его не переводят. Он выводится как есть и помечается `lang` того языка, на котором пришёл. **[утв.]**

Контент backend помечается через `<BackendText>` и `BACKEND_CONTENT_LANG` из `ui/shared/i18n`, а не литералом `lang="ru"`. Кириллица в коде — только в словарях `ui/shared/i18n/locales/**.json` и JSON фикстур; это касается и `tests/`, `e2e/`, `docker/`, `index.html`. Заголовок вкладки ставит `LocaleProvider` (`common:app.title`). **[предл.]**

## 4. Стили

**[утв.]** Никаких огромных CSS. Стили локальные, без повторений, общее переиспользуется.

- Глобальный CSS живёт только в `ui/shared/styles/`. Это `global.css`, который подключает `reset.css` и `tokens/{color,typography,space,radius,motion,keyframes}.css`. `global.css` импортируется один раз в `main.tsx`. **[предл.]**
- Всё остальное — CSS Modules рядом с компонентом. Модуль импортирует только его собственный компонент, неиспользуемых классов нет. **[предл.]**
- Цвета, длительности, кривые, тени и радиусы задаются литералами только в `tokens/`. В остальных местах — только `var(--…)`. Проверяется `scripts/checks/css-literals` и `css-token-refs`. **[предл.]**
- Блок из 3+ одинаковых деклараций в двух местах запрещён: такой блок становится компонентом или токеном. Проверка — `scripts/checks/css-duplicates`. **[предл.]**
- Компонент объявляет свои локальные custom properties (`.button { --button-surface: var(--surface-card) }`), модификаторы их только переопределяют. **[предл.]**
- Классы собираются через `clsx`, варианты — через карту `Record<Variant, string>`. **[предл.]**
- Брейкпоинты: только `30/48/64/75rem`. **[предл.]**

### Дизайн-система

Источник — [tokens.md](tokens.md) (Zoox, **[утв.]** целиком). В код он переносится как два слоя: **[предл.]**

1. **Палитра** (`--sage-canvas`, `--carbon`, `--vivid-teal` и т. д.): сырые значения из `tokens.md`.
2. **Семантика** (`--surface-canvas`, `--surface-card`, `--text-primary`, `--text-secondary`, `--action-primary`, `--border-hairline`, `--focus-ring`): ссылки на палитру. Компоненты используют только семантический слой.

Конфликты Zoox с нашим продуктом:

- **Плотность.** Zoox — «showroom, not a dashboard», а у нас именно панель с картой и телеметрией. Предлагаю иерархию радиусов **[предл.]**:
  - 36px с паддингом 24px — у верхнеуровневых карточек;
  - 16px — у вложенных блоков;
  - 12px — у кнопок.
  - Отступ между секциями — 24–40px вместо 80–120px. Шрифт display 56/120px только на заставке и в пустом состоянии.
- **Один хроматический цвет.** Zoox запрещает другие цвета, а карте и состояниям нужны отличимые сущности: образец, опасная зона, стоимость грунта, второй робот, ошибка или Stop. **[утв.]** Отдельный слой `--data-*` (и сигнальные `--signal-*`) только для визуализаций данных: карта, полоса `Meter`, графики. Решение координатора 2026-10-08 по поручению пользователя: в тексте, бейджах, иконках, кнопках и фонах интерфейса сигнальных цветов нет; там предупреждение передаётся иконкой, весом и Carbon. Проверка повторов CSS не считает свойства раскладки (`display`, `align-items`, `gap` и т. п.) и пользовательские `--*`. Слой `--data-*` приглушённый и согласованный с sage. Интерфейсный слой при этом строго по Zoox.
- **Шрифты.** **[утв.]** Шрифт из визуальной темы: GT Standard S и GT Standard L, как в `tokens.md`. Подключаются локально из `public/fonts`, а не с CDN, потому что на финале может не быть сети. Если файлов нет, работает fallback-стек из `tokens.md`.
- **[вопрос]** На 2026-10-08 лицензированных файлов GT Standard в проекте нет, работает Inter / Inter Display из `public/fonts` (OFL). Нужны файлы GT или подтверждение, что Inter — утверждённая замена.
- **Canvas карты.** `mapRenderer.ts` рисует literal-цветами. Цвета карты читаются из CSS-токенов одной функцией (`readCanvasPalette()` через `getComputedStyle`) и обновляются при смене темы. **[предл.]**
- **Тени.** Нет, кроме `--shadow-sm` у всплывающих диалогов, как в Zoox. **[предл.]**
- **Тёмная тема.** Zoox светлый, тёмной темы нет. **[предл.]**
- **Стиль «Лаборатория».** [visual-style.md](visual-style.md) с ним конфликтует. **[утв.]** 2026-10-08 пользователь сказал: «визуальный стиль везде един». Мой вывод: Zoox — единственный стиль для панели, презентации, экспортов и всего остального, а «Лаборатория» отменяется. Если вывод неверен, это нужно поправить.

## 5. Анимации

**[утв.]** Анимировано всё. Скиллы — в `.claude/skills/`, скопированы из GoatWhistle: `emil-design-eng`, `review-animations` (+ `STANDARDS.md`), `improve-animations`, `find-animation-opportunities`, `animation-vocabulary`.

Токены `tokens/motion.css` (кривые дословно из скиллов): **[предл.]**

```
--ease-out:     cubic-bezier(0.23, 1, 0.32, 1)
--ease-in-out:  cubic-bezier(0.77, 0, 0.175, 1)
--ease-drawer:  cubic-bezier(0.32, 0.72, 0, 1)
--dur-instant 80ms   --dur-press 140ms   --dur-fast 160ms   --dur-fast-exit 110ms
--dur-base 200ms     --dur-exit 140ms    --dur-panel 260ms  --dur-slow 320ms
--dur-draw 900ms     --dur-breathe 2600ms
--delay-skeleton 200ms   --stagger 40ms   --press-scale 0.97   --press-scale-surface 0.99
--reduced-fade 160ms
```

Длительности — середина диапазонов из `STANDARDS.md`. Под Zoox они подобраны спокойнее: без резких 70ms. Значения проверяются на живой панели и могут сдвигаться только внутри `tokens/motion.css`.

Во всех четырёх прошлых проектах анимировано всё: у каждого типа элемента есть заданное поведение. Движение собрано в общие примитивы и токены, а соблюдение правил проверяют тесты.

### 5.1 Общие правила

**[предл.]**

- Анимируются только `transform`, `opacity`, `clip-path` и `filter: blur` не больше 2px. Свойства `width`/`height`, `transition: all`, `ease-in` и `scale(0)` запрещены. Вход начинается от `scale(0.95)` + `opacity: 0`.
- Выход быстрее входа. UI-анимации короче 300ms. Длинные допустимы только для редких событий: рисования линии пути, сбора образца, заставки.
- Без bounce. Пружины — только у перетаскивания, если оно появится.
- Длительности и кривые литералами пишутся только в `tokens/motion.css`. Keyframes объявляются в `tokens/keyframes.css`, компонент получает их через токен `--motion-*`. Так CSS Modules не переименовывают имена анимаций.
- JS берёт тайминги из тех же токенов через `motionMs("--dur-base")` (паттерн assembly). В TS не бывает чисел-миллисекунд.
- Hover работает только внутри `@media (hover: hover) and (pointer: fine)`. Фокус не анимируется, у него один общий `:focus-visible`.
- Действия с клавиатуры не анимируются.
- Библиотек анимации нет: только CSS, WAAPI и View Transitions.

### 5.2 Частота решает, что анимировать

Телеметрия приходит примерно 10 раз в секунду. Поэтому:

| Как часто | Что | Как |
| --- | --- | --- |
| Каждый тик | Числа батареи, сигнала и времени | Без анимации. Шрифт `tabular-nums`, чтобы цифры не прыгали |
| Каждый тик | Полоса батареи | `transform: scaleX` за `--dur-base`, кривая linear: переход перенацеливается каждый тик |
| Каждый тик | Поза робота на карте | Интерполяция на `requestAnimationFrame` между кадрами, без keyframes |
| Секунды | Текущая подцель и шаг плана | Индикатор только через transform. Смена текста — `Swap` |
| Редко | Новая запись журнала, вывод гипотезы, сбор образца, опасность, смена режима, потеря партнёра | Выразительное событие (таблица 5.3) |
| Однажды | Первая загрузка панели | Лесенка панелей |

Этот принцип проверен в assembly: строки живого транскрипта там не анимируются, и это закреплено тестом. Двигаются только редкие события.

### 5.3 Что и как анимируется в нашей панели

**[предл.]**

| Элемент | Анимация | Токены |
| --- | --- | --- |
| Кнопки Start, Stop, экспорт: наведение | `--transition-control` | `--dur-fast`, `--ease-out` |
| Кнопки: нажатие | `:active { scale: var(--press-scale) }` = 0.97; у карточек 0.99. Нажатие медленнее отпускания: вход `--transition-control-press`, возврат `--transition-control` | `--dur-press` / `--dur-instant` |
| Сценарий easy/medium/hard, режим карты, язык | `Segmented`: бегунок FLIP через WAAPI, включается после первого кадра | `--dur-base` |
| Смена языка | Как в rlt: меню открывается и закрывается анимацией `Menu`, галочка и индикатор переезжают по transform, меню закрывается через `settleDelay` 220ms. Текст интерфейса меняется сразу | `--dur-fast`, `--dur-base` |
| Состояние миссии idle → starting → running → returning → completed/failed | Бейдж статуса меняется через `Swap`. Перестройка раскладки — через `withViewTransition("mission")` | `--dur-base`, лимит 900ms |
| Первая загрузка | Карточки въезжают лесенкой: `--motion-slide-in`, задержка `calc(var(--i) * var(--stagger))` | `--stagger` 40ms |
| Загрузка данных | Скелет через 200ms, держится минимум 300ms. Спиннер через 400ms. Если данные уже есть, используется затемнение `stale` по opacity (политика GoatWhistle) | `--delay-skeleton` |
| Плашка «данные устарели» и потеря связи | Переходы clip-path + opacity по `data-state` (`--transition-reveal-*`), вход через `@starting-style`; мигание состояния не перезапускает анимацию | `--dur-base` / `--dur-exit` |
| Живой прогон | Точка «в эфире» мягко пульсирует, `--motion-pulse` | `--dur-breathe` |
| Батарея ниже резерва возврата | Однократная вспышка фона полосы (`commit`) и иконка | `--dur-slow` |
| Новый план LLM или fallback | Старый план уходит, новый входит через `Swap`. Шаги входят лесенкой | `--dur-base`, `--stagger` |
| Выполненный шаг плана | Отметка появляется с `--motion-pop-in` | `--dur-fast` |
| Новая гипотеза в журнале | `--motion-rise-in`: 6px + opacity | `--dur-slow` |
| Вывод «подтверждена / опровергнута / мало данных» | `verdict`: у каждого исхода своё движение и иконка, а не только цвет | `--dur-base` |
| Раскрытие записи журнала | `useDetailsMotion`: переходы clip-path и opacity, без height; повторный клик во время закрытия разворачивает обратно с текущего кадра | `--dur-panel` / `--dur-panel-exit` |
| Карта: новый маршрут | Линия рисуется по `dashoffset` | `--dur-draw` |
| Карта: сбор образца | Метка: pop, затем угасает кольцо | `--dur-slow` |
| Карта: найденная опасность | Кольцо `appear-mark` (толстый штрих, который становится тонким) | `--dur-slow` |
| Карта: обновление оценки грунта | Цвет клетки плавно интерполируется на canvas | `--dur-slow` |
| Карта: бронь второго робота | Контур проявляется по opacity | `--dur-base` |
| Строка робота в TeamPanel | Смена статуса — `Swap`. Потеря партнёра — `verdict-emphatic` | |
| Диалоги и экспорт | Подложка — `--motion-fade-*`, панель — `--motion-scale-*` | `--dur-base` / `--dur-exit` |
| Тултипы | Fade + scale 0.95 от стороны якоря, переходами; следующий тултип в пределах задержки — без анимации; Esc закрывает, на тултип можно навести курсор | `--dur-fast` / `--dur-fast-exit` |
| Выпадающий список `Select`, `Menu`, `Popover` | Открытие: fade + scale 0.95→1 + сдвиг 4px от стороны якоря, `transform-origin` у якоря, переходами с `@starting-style` (повторное открытие во время закрытия идёт с текущего кадра). Закрытие быстрее. Галочка `Menu` переходом появляется только при смене выбора; у `Select` галочка без анимации (список закрывается при выборе). Подсветка пункта не анимируется | `--dur-fast` / `--dur-fast-exit` |
| `Checkbox`, `Switch`, `RadioGroup` | Галочка рисуется по `stroke-dashoffset`, бегунок `Switch` едет через transform, точка радио появляется переходом opacity + scale. С клавиатуры — без анимации (`useInputModality`) | `--dur-fast` |
| `NumberField` | Нажатие кнопок шага — press. Само число не анимируется | `--dur-press` |
| Полосы прокрутки | Ползунок проявляется по opacity при прокрутке и наведении, гаснет после паузы. Затухание у краёв области через `animation-timeline: scroll()` с fallback | `--dur-base` |
| Пустое состояние и ошибка | `--motion-slide-in` | `--dur-slow` |

Canvas не читает CSS-переменные сам. Длительности он получает через `motionMs`, кривые — через `readEasing("--ease-out")`, и всё это повторяет CSS-кривую. Анимация на canvas проверяет reduced motion так же, как CSS.

### 5.4 Общие примитивы `ui/shared/motion/`

**[предл.]** Это объединение лучших примитивов из прошлых проектов. Других способов анимировать в коде нет.

- `usePresence(open)` → `{ mounted, state, onAnimationEnd }`. Компонент размонтируется по `animationend` или по резервному таймеру (rlt).
- `useLatched(value, open)` — закрывающийся элемент продолжает показывать прежнее содержимое (interrao).
- **[утв.]** Все элементы управления свои, не системные: полосы прокрутки, выпадающие списки, меню, флажки, переключатели, числа. У каждого всплывающего или раскрывающегося элемента есть анимация открытия и закрытия.
- `<Swap swapKey>` — сначала уходит старое (WAAPI `leave`), потом входит новое. Высота фиксируется на время смены (assembly + GoatWhistle).
- `useSlidingIndicator` — бегунок у `Segmented` и вкладок (GoatWhistle, rlt).
- `withViewTransition(mode, change)` — оборачивает смену с лимитом 900ms. Без поддержки API или при reduced motion изменение применяется сразу (rlt).
- `motionMs(token)`, `readEasing(token)`, `useReducedMotion()` через `useSyncExternalStore` (assembly).
- `useLoadingIndicator({ pending, hasData })` → `none | skeleton | spinner | stale` (GoatWhistle).

### 5.5 Reduced motion

**[предл.]** Принцип «мягче, а не ноль»:

- все `--dur-*` становятся 1ms, `--stagger` — 0, смещения и `scale` нейтрализуются;
- элементы с `data-motion="fade"` (вход панелей, вердикты, `Swap`, слои, плашки) получают короткий fade `--reduced-fade` 160ms на вход и `--reduced-fade-exit` 110ms на выход, чтобы смена и закрытие были заметны; резервные таймеры примитивов ждут этот fade;
- пульс и спиннер становятся статичными; вместо спиннера показывается текст стадии;
- робот на карте прыгает в новую позу без интерполяции; линия маршрута появляется сразу.

### 5.6 Тесты движения

**[предл.]** Сборный набор assembly и GoatWhistle:

- В CSS вне `tokens/` нет литеральных ms, `cubic-bezier`, `steps(` и `!important`.
- Каждый `--motion-*` ссылается на существующий keyframe. В keyframes только transform, opacity, clip-path и filter.
- Каждый `--dur-*-exit` короче соответствующего входа. Токена `--ease-in` не существует.
- Reduced motion сжимает каждый `--dur-*`.
- Для каждого элемента таблицы 5.3 есть поведенческий тест: элемент получает `data-state` или класс анимации. Пример: «бейдж статуса меняется через Swap».
- Числа телеметрии не анимируются. Это проверяет отдельный тест, по образцу assembly «does not animate running transcript text».
- Вердикты гипотез различаются движением и иконкой, а не только цветом.
- `usePresence`, `Swap`, `withViewTransition` и `useLoadingIndicator` покрыты юнит-тестами, включая reduced motion.
- Перед сдачей фичи с движением её проходят скиллом `review-animations`.

## 5а. Единый визуальный стиль

**[утв.]** Визуальный стиль везде един: панель, презентация, экспорт журнала, заставка и любые новые экраны.

### Один источник

- Источник — [tokens.md](tokens.md). Код читает его только через `ui/shared/styles/tokens/`.
- Презентация и любые HTML-материалы подключают те же токены: копию CSS, которую собирает скрипт, а не значения, переписанные руками. **[предл.]**
- Иконки — один набор. **[утв.]** `lucide-react` с обводкой 1.5 и одним каноническим именем на иконку.

### Фиксированные шкалы

**[предл.]** Другие значения запрещены тестом.

| Шкала | Значения |

### Тесты единства

**[предл.]**

- Шкалы: радиусы, тени, размеры текста и брейкпоинты только из токенов.
- Слои токенов: компоненты используют только семантический слой, палитру напрямую не берут.
- Ровная лестница поверхностей.
- Тесты `*-consistency` для каждой роли из таблицы выше.
- `icon-alias`: одна иконка — одно имя.
- `no-side-stripe`.
- Контраст не ниже 4.5:1, цели нажатия не меньше 44px.
- Тест «на всех экранах один и тот же набор токенов»: презентация и панель подключают один CSS токенов.

## 6. Скиллы для интерфейса

- **[утв.]** Весь фронтенд делается со скиллами `impeccable` и `ui-ux-pro-max`.
- **[предл.]** Скиллы работают внутри этих правил. Палитры с сырым hex из `ui-ux-pro-max` не берём: только токены из `tokens.md`. У `ui-ux-pro-max` берём структуру, доступность и UX-проверки.
- **[предл.]** `impeccable init` не запускаем: он создал бы второй `DESIGN.md`/`PRODUCT.md` и второй источник правды рядом с `tokens.md`.
- **[предл.]** Анимации ревьюим скиллом `review-animations` перед сдачей фичи.

## 7. Доступность

**[предл.]**

- Контраст текста не ниже 4.5:1. На sage `#d3e4df` это значит: Mist `#7b8889` и Fog `#9aa3a5` не подходят для текста. Это нужно проверить тестом контраста и, вероятно, затемнить их в семантическом слое.
- Teal `#64d5b3` — только поверхность, текст на ней Carbon.
- Цель нажатия не меньше 44px.
- Видимый `:focus-visible` из токена `--focus-ring`.
- Состояние не передаётся только цветом: у статуса есть текст или иконка.

## 8. Инструменты и проверки

**[предл.]**
