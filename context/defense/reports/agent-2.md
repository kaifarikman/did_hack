# Отчёт агента 2: интерфейс выбора точки (D1)

Статус: реализовано и проверено **на fixture-стенде**. Это не живой Gazebo и не настоящий backend; в панели fixture подписан «Демо-данные».

## Что сделано

- Контракт: state `1.4` (`task_type`, `navigation`), `health.supported_task_types`, `StartRunRequest.task_type/navigation_target`. State 1.0–1.3 читаются как research/null; в 1.4 поля обязательны, `task_type=navigation` без объекта цели отклоняется. Нет поля `supported_task_types` → только research, навигация не предлагается.
- Выбор «Исследование» / «В заданную точку». Профиль навигации фиксирован: easy / static / 1 робот; текст миссии не отправляется.
- Цель: поля X/Y (клавиатура, десятичная запятая допустима) и клик по карте. Клик только выбирает точку; на карте штриховой маркер «Выбрано», под полями — пояснение. Координаты клика округляются до мм и показываются ровно такими, какие уйдут в запрос вместе с `map_id`.
- Преобразование клик → мир: `canvasClickToWorld`, `cellAtWorld`, `worldToLocal` (`src/domain/geometry.ts`): origin и поворот карты, перевёрнутая ось Y, отступы, масштаб страницы (через rect); `devicePixelRatio` не влияет. Клик вне карты игнорируется с пояснением.
- Актуальность: Start недоступен при несовпадении карты, смене `map_id` после выбора и после потери связи (нужна кнопка «Подтвердить точку»). Достижимость UI не утверждает; клетка-стена/неизвестная — предупреждение, решает backend.
- Во время активной миссии цель заблокирована (поля, клик, переключатель типа).
- Отображение: «Цель пользователя» (точка, допуск, достигнута/нет), этап, подцель робота отдельно, маршрут и revision, цепочка этапов (проверка → движение → цель достигнута → возврат → finish), итог. «Цель достигнута» без finish показывается как прогресс; успех — только `completed` + `finished` + достигнута; `navigation_goal_not_reached` → отказ; Stop → прервано.
- Ошибки D1 (`navigation_target_unreachable`, `map_changed`, `run_conflict`, `scenario_unavailable`, `environment_not_ready`, `invalid_request`) — русские сообщения без текста backend. После `map_changed` карта перечитывается сразу; новый запуск получает новый request_id. Unknown-outcome/retry с тем же request_id, Stop, reconnect, экспорт — сохранены.
- Fixture-сценарии (выпадающий список «Сценарий демо»): `nav_success`, `nav_not_reached`, `nav_map_changed`, `nav_refused`, `nav_disconnect`; стена/вне карты проверяются реальной геометрией fixture-карты (BFS по сетке); Stop работает в любом. Файлы fixture только внутри `frontend/`; sync-скрипт не запускался.

## Ограничения

- Не проверено с настоящим backend; fixture-planner грубее реального (4-связность, без инфляции).
- Тесты React-компонентов отсутствуют (среда vitest — node); UI проверен вручную.
- После завершения прогона штриховой маркер черновика остаётся поверх достигнутой цели, пока пользователь не сменит точку.
- Клик на узком экране проверен лишь синтетически (не подтверждён).
- Существующие общие примеры `context/mvp/examples` и их копии в `frontend` не менялись (остаются 1.3).

## Сценарий для агента 3

1. Открыть панель, выбрать «В заданную точку». Убедиться, что `/api/v1/health` содержит `supported_task_types: ["research","navigation"]`.
2. Дождаться карты; кликнуть по свободной клетке на карте (или ввести X/Y). Проверить, что робот не двигается, а под полями указаны X/Y и map_id.
3. Нажать «Запустить к точке»: в запросе `task_type=navigation`, `navigation_target{x,y,map_id}`, `scenario=easy`, `map_mode=static`, `robot_count=1`.
4. Наблюдать этапы: проверка → движение (маршрут на карте) → «Цель достигнута, миссия ещё не завершена» → возврат → «Цель достигнута, робот вернулся на базу» только после completed.
5. Отдельно: клик по стене (ожидается 422 с сообщением), Stop во время движения (stopped, робот физически стоит), потеря связи (баннер «Данные устарели»).
