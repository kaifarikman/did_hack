# Расширение: навигация, аналитика и несколько агентов

Дата: 2026-10-07. Статус: предложение архитектуры для обсуждения, не реализованная функциональность. Пользователь запросил включить обе идеи и спроектировать мультиагентную систему с ограниченным контекстом. Конкретное число ролей, бюджет и хранилище ниже предложены командой; это не требования организаторов.

## Что добавляем в целевой план

1. Надёжная навигация: проверка коридора, временные препятствия, отклонение от пути, безопасное восстановление и прогноз возврата.
2. Единая наблюдаемость: структурированные решения, измерения, прогнозы и причины переходов в существующем JSONL и React-панели.
3. Три роли с LLM: оркестратор, исследователь, аналитик-критик. Их предложения проверяет алгоритмическое ядро; контур движения работает независимо.
4. Ограниченная рабочая память: актуальный снимок, короткий набор свидетельств, запрос деталей по идентификаторам. Полная история хранится вне промпта.
5. Независимый разбор серий с одинаковыми сценариями для сравниваемых стратегий; скрытая истина доступна только оценщику после прогона.

## Что в идеях следует изменить

| Идея источника | Решение проекта |
| --- | --- |
| Возврат при батарее <15% | Решение по стоимости реального пути домой + неопределённость + резерв восстановления. Фиксированный процент может быть дополнительным индикатором панели, но не достаточным условием безопасности |
| MSE сильнее наказывает недопрогноз | Квадрат симметричен знаку ошибки. Отдельно измерять опасный недопрогноз и покрытие верхней оценки, помимо RMSE |
| `bias > 0` означает недооценку | Явно задать ошибку `actual - predicted`; только при таком определении положительное среднее означает недопрогноз |
| `MSE = bias² + variance` | Для остатка верно `mean(e²) = mean(e)² + Var(e)` с согласованной нормировкой. Не выдавать это за полное разложение ошибки обучаемой модели без определения шума и повторных выборок |
| ε=0.5 Вт·ч/м | В текущей модели стоимость задана в единицах батареи на метр. Порог выбрать в этих единицах; физические Вт·ч не вводить без калибровки |
| RMSE по истинной карте в health_summary | В онлайн-сводке только ошибка прогноза по независимым доступным измерениям. Ошибка по скрытой истинной карте — только в офлайн-отчёте |
| Точки образцов на живой карте | Только наблюдённые/подтверждённые точки. Истинные координаты — отдельный разбор после прогона |
| `samples_remaining_est` | Nullable-оценка с основанием и неопределённостью; не подставлять скрытое истинное число |
| Температура 0 делает эксперимент повторяемым | Фиксировать настройки, модель, запросы и ответы. Повторяемость проверять повторными прогонами; нулевая температура сама по себе не гарантия |
| 3–5 seeds, bootstrap CI, Wilcoxon | Это начальная диагностическая серия, а не гарантия статистической убедительности. Показывать все парные результаты и провалы; метод и объём финального сравнения зафиксировать до контрольных запусков |
| «Adaptive выигрывает 4/5» | Только проверяемая гипотеза, не заготовленный результат питча |
| Streamlit/Dash рядом с React | Расширять существующую панель; отдельный сайт сейчас дублирует данные и контракты |
| Новая EMA-карта грунта | Сначала проверить существующий TerrainEstimator. Сглаживание не должно стирать границы зон или выдавать догадку за измерение |
| Самооценка уверенности LLM | Хранить отдельно от измеренной надёжности. Не использовать как основание разрешить движение или подтвердить гипотезу |
| Логирование на каждом тике | Телеметрия с ограниченной частотой и события переходов. Очередь/буфер не блокируют управление; переполнение видно в диагностике |

При нуле сборов `battery_per_sample` не равен нулю: значение отсутствует, а неуспешные прогоны остаются в выборке. Остановленные миссии не исключаются из оценки успешности. Недостигнутая цель имеет исход failed/timeout, а не выдуманное время достижения.

## Граница текущей работы

В этом изменении сохранены источники и подготовлен проект расширения. Новые runtime-агенты не запущены, код движения не изменён, новые прогоны не выполнены. Состояние существующей интеграции см. в [отчёте](../reports/integration-2026-10-07.md): параллельно меняются ROS-адаптеры, поэтому их завершённость проверять по коду и свежим свидетельствам.
