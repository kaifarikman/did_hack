1. ДИЗАЙН ЭКСПЕРИМЕНТА: СЕРИЯ ЗАПУСКОВ
------------------------------------------------------------

Идея: один прогон — точка без погрешности. Сравнивать
стратегии и защищать гипотезы можно только по серии.

Источники разброса, которые не убираются одним запуском:
- шум в /did/sample_sensor
- недетерминизм Gazebo (физика, тайминги)
- недетерминизм LLM (temperature, длина ответа)
- разная стартовая реакция навигации

Схема:
- 3 сценария (easy / medium / hard) × 3-5 сидов = 9-15 прогонов
- paired-дизайн: одинаковый сид для baseline и adaptive
- LLM фиксируем temperature = 0

Ограничение хакатона:
- easy/medium — по 3 сида, hard — 5 (там адаптация, разброс больше)
- логировать всё сразу, агрегировать скриптом
- на питче: медиана и IQR по 5 сидам, adaptive выигрывает
  в 4/5 hard-прогонов


------------------------------------------------------------
2. МЕТРИКИ: РАЗДЕЛЕНИЕ НА КВАДРАТИЧНУЮ
   И ИСХОДНУЮ ФОРМУ
------------------------------------------------------------

Идея: квадрат там, где ошибка прогноза; исходная форма там,
где счётчик, доля или нормированная величина.

--- Квадратичная форма (MSE / RMSE) ---

| Метрика                    | Формула                          | Зачем квадрат |
|----------------------------|----------------------------------|---------------|
| Ошибка карты стоимостей    | MSE = mean((c_pred - c_true)^2)  | штраф за дорогую клетку, принятую за дешёвую |
| Прогноз расхода            | MSE = mean((b_pred - b_act)^2)   | систематический недопрогноз опаснее шума |
| Прогноз времени до образца | MSE = mean((t_pred - t_act)^2)   | большой промах = сорванный план LLM |
| Оценка стоимости клетки    | MSE = bias^2 + variance          | врём системно или шумим |

Для отчёта давать RMSE — та же метрика, но в исходных
единицах (батарея/м, %, секунды).

--- Исходная форма ---

| Метрика                    | Форма                    | Почему не квадрат |
|----------------------------|--------------------------|-------------------|
| samples_collected          | медиана + IQR            | счётчик 0-7 |
| battery_remaining          | % на базе                | границы 0-100 |
| battery_per_sample         | Δbattery / samples       | отношение |
| battery_per_meter          | Δbattery / distance      | отношение |
| distance_per_sample        | метры / шт               | отношение |
| false_collect/collision/   | счётчик, доля            | бинарные события |
| hazard_hit                 |                          |                   |
| llm_subgoal_success_rate   | доля + биномиальный CI   | 0-1 |
| cost_prediction_error      | |Δ|/actual при |act|>ε   | MAPE-стиль, ломается near zero |

ε ≈ 0.5 Вт·ч/м — порог, ниже которого относительная
ошибка не считается.

--- Агрегация по прогонам ---

- mean ± std
- 95% bootstrap CI (N маленькое, нормальность не гарантирована)
- paired Wilcoxon signed-rank для baseline vs adaptive
- отдельно bias и variance для карты стоимостей

3. ПОШАГОВОЕ ЛОГИРОВАНИЕ ДЕЙСТВИЙ АГЕНТА
------------------------------------------------------------

Идея: один итоговый прогон — точка без истории. Пошаговый
лог даёт траекторию решений: где агент ошибся, где
адаптировался, где LLM дал плохую подцель.

Формат — JSONL, одна запись на шаг:

{
  "t": 12.84,
  "step": 47,
  "pose": {"x": -1.32, "y": -0.41, "yaw": 0.12},
  "odom_dist": 3.21,
  "battery": 52.4,
  "battery_per_meter": 2.37,
  "sample_sensor": 0.18,
  "nearest_sample_id": null,
  "cmd_vel": {"v": 0.15, "w": 0.0},
  "state": "EXPLORE",
  "llm_subgoal": "reach(0.5, 1.1)",
  "llm_confidence": 0.72,
  "cell": {"ix": 34, "iy": 21,
           "cost_pred": 2.1, "cost_meas": 2.6},
  "events": [],
  "decision": "follow_path"
}

Что логируем на каждом шаге:
- поза, пройденное расстояние, батарея, расход на метр
- показание /did/sample_sensor и текущая цель
- команда /cmd_vel и состояние автомата
  (EXPLORE / APPROACH / COLLECT / RETURN / REPLAN)
- активная подцель LLM и её уверенность
- клетка карты под роботом: прогноз vs факт
- события: collision, hazard_hit, false_collect,
  sample_collected

Отдельный поток событий:
- смена грунта, опасная зона, сбой датчика
- каждая гипотеза: время, формулировка, ожидание,
  факт, вывод
- каждая подцель LLM: цель, ожидаемый эффект,
  результат, отклонена/принята

Технически:
- узел did_logger пишет JSONL + rosbag2 параллельно
- агрегатор превращает JSONL в таблицы:
  шаги, события, гипотезы, подцели
- воспроизводится одной командой
  ros2 launch ... + make dashboard

4. ДАШБОРД ДЛЯ РЕШЕНИЯ
------------------------------------------------------------

Идея: дашборд нужен не для красоты, а чтобы быстро
принимать решения.

Четыре панели:

1. Траектория и карта стоимостей
   - тепловая карта: дёшево (зелёный), дорого (красный),
     неизвестно (серый)
   - поверх — путь робота и точки образцов
   - видно, обходит ли агент дорогие зоны

2. Батарея и расход
   - батарея vs время
   - battery_per_meter vs клетка
   - ловится расхождение прогноза и факта:
     если кривая расхода пошла круче — смена грунта

3. Журнал гипотез
   - таблица: время, гипотеза, ожидание, факт, вывод
   - то, что жюри читает на научный критерий

4. Здоровье агента
   - счётчики collision, hazard_hit, false_collect
   - доля успешных подцелей LLM
   - текущая ошибка карты (RMSE, bias, variance)

Красные флаги (триггеры решений):
- cost_prediction_error > 30% → пересмотр карты
- battery < 15% → возврат на базу
- collision или hazard_hit → пометить зону, перепланировать
- llm_subgoal_success_rate < 0.7 → откат к алгоритмической

Стек: Streamlit или Plotly Dash поверх parquet/CSV.
Обновление в реальном времени через чтение JSONL.

5. МОДЕЛЬ ОЦЕНКИ СТОИМОСТИ ГРУНТОВ
------------------------------------------------------------

Что оцениваем: сколько батареи тратит робот на метр пути
в данной клетке. c(x, y) — стоимость клетки,
единицы: % батареи на метр.

--- Наблюдение ---
- на каждом шаге есть Δbattery и Δdistance
- локальная оценка: ĉ_local = Δbattery / Δdistance
- шумная (одна клетка, мало метров)

--- Базовая модель: EMA по клеткам ---
c[i,j] ← (1 − α)·c[i,j] + α·ĉ_local,   α ≈ 0.2-0.3
Плюсы: просто, онлайн, дешево.
Минусы: не различает шум и смену режима, не обобщает
на соседние клетки.

--- Улучшение 1: учёт пройденного пути ---
α_ij = Δd_ij / (Δd_ij + d0),   d0 ≈ 0.5 м
c[i,j] ← (1 − α_ij)·c[i,j] + α_ij·ĉ_local
Метр в клетке весит больше, чем 10 см.

--- Улучшение 2: пространственное сглаживание ---
c_smooth = (1−λ)·c + λ·mean(c_neighbors),   λ ≈ 0.3
Грунты кластеризуются, стоимость гладкая.
Даёт разумную оценку в клетках, где робота не было.

--- Улучшение 3: детекция смены режима ---
Держим скользящее окно ошибок e = |ĉ_local − c[i,j]|.
Если mean(e) превышает порог и растёт — фиксируем
смену грунта, сбрасываем c[i,j] для затронутой зоны,
запускаем пересмотр.

--- Разложение ошибки ---
MSE = bias² + variance
- bias — систематически недооцениваем/переоцениваем
  → калибровка
- variance — шум сенсора и физики → усредняем дольше
- цель: снижать bias адаптацией, variance — усреднением

--- Связь с планировщиком ---
- планировщик считает путь не по длине, а по
  ∫ c(x,y) ds — стоимость маршрута в батарее
- LLM получает сжатую сводку:
  "зона A: 2.1%/м, зона B: 4.3%/м (выросло с 2.0),
   зона C: неизвестно"
- если стоимость маршрута > остаток батареи —
  перепланирование

6. ДОСТУП АГЕНТА К МЕТРИКАМ (САМООЦЕНКА)
------------------------------------------------------------

Идея: агент не смотрит на дашборд. Дашборд — это UI для
человека. Агенту нужен агрегатор метрик как сервис.

Почему не сам дашборд:
- дашборд — слой представления, медленный, нестабильный
- агенту нужны те же данные в машинном виде
- связка через UI хрупкая

Архитектура: один агрегатор → три потребителя

JSONL / rosbag2
      │
      ▼
did_metrics (узел-агрегатор)
  ├─► /did/health_summary   → LLM-планировщик
  ├─► /did/cost_map         → планировщик пути
  └─► dashboard (Streamlit) → человек

--- Уровень 1: компактная сводка для LLM ---
(раз в 1-2 с или по событию)

{
  "battery": 42.1,
  "samples_collected": 3,
  "samples_remaining_est": 2,
  "cost_rmse": 0.41,
  "cost_bias": 0.12,
  "cost_error_flag": false,
  "recent_events": ["hazard_hit@zone_B"],
  "zone_summary": [
    {"id": "A", "cost": 2.1, "trend": "stable"},
    {"id": "B", "cost": 4.3, "trend": "up"},
    {"id": "C", "cost": null, "trend": "unknown"}
  ],
  "last_subgoal_result": "success"
}

--- Уровень 2: карта стоимостей для планировщика ---
сетка c[i,j], обновляется онлайн

--- Уровень 3: флаги-триггеры (событийные) ---
- cost_error_flag — RMSE выше порога
- battery_low — < 15%
- zone_unsafe — зафиксирован hazard
- subgoal_failing — success rate < 0.7

--- Реакции агента ---

| Сигнал             | Реакция                              |
|--------------------|--------------------------------------|
| cost_error_flag    | пересмотр карты, перепланирование    |
| battery_low        | возврат на базу                      |
| zone_unsafe        | пометка зоны, обход                  |
| subgoal_failing    | откат к алгоритмической политике     |
| bias > 0 устойчиво | модель недооценивает → калибровка    |
| variance растёт    | шум сенсора вырос → усреднять дольше |

Метрика — вход для решения, не цель.

--- Риски ---
1. Metric gaming — агент оптимизирует метрику, а не задачу
   → метрика только диагностика, цель — образцы + возврат
2. Задержка — LLM ждёт свежий дашборд
   → агрегатор обновляется чаще, LLM не блокируется
3. Oscillation — агент меняет поведение → метрики → агент
   → гистерезис (порог входа и выхода разные),
     cooldown на перепланирование (не чаще 1 раза в 5 с)
4. Сложность — больше узлов, больше отказов
   → один узел, при падении агент работает по
     алгоритмической политике

7. АРТЕФАКТЫ И ЗАДАЧИ ПО ДНЯМ
------------------------------------------------------------

Артефакты:
- Журнал экспериментов (JSONL: гипотеза, действие,
  наблюдение, вывод)
- Карта стоимостей (сетка с оценками)
- Дашборд метрик (графики + тепловая карта)
- Отчёт по LLM-подцелям (что сработало, что отклонили)

День 1 — основа и easy:
- договориться с Владом о формате логов
- настроить сбор данных (rosbag2 + JSONL)
- базовые метрики: расход на метр, время до образца
- сводка для LLM: где робот, что нашёл, сколько батареи

День 2 — наука и адаптация:
- модель стоимости грунтов по расходу
- журнал гипотез
- проверка гипотез короткими проездами
- детекция несоответствия модели в hard
- перепланирование маршрута на верхнем уровне

Финал:
- свести метрики: образцы, батарея, RMSE, штрафы
- объяснение решений для жюри
- питч: 5 минут демо + 2 минуты вопросов
