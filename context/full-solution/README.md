## Что считаем сильным решением

Агент ищет скрытые образцы только по разрешённым наблюдениям, оценивает энергию маршрутов, проверяет гипотезы действием, замечает необъявленные изменения и пересматривает план. Он стремится собрать больше образцов, сохраняя возможность возврата. LLM участвует в выборе плана и объясняет его; движение и ограничения проверяются алгоритмически. Демо и журнал показывают фактические измерения.

«Корректно» означает соблюдение контрактов, отсутствие доступа агента к скрытой истине, проверяемые эксперименты и предсказуемое поведение при сбоях. Это не обещание математически оптимального сбора или успешного возврата при любой возможной поломке. Для физически неразрешимых случаев нужен честный исход с объяснением. Условия решаемости испытательных сценариев фиксируются отдельно.

## Что уже есть и что нужно развить

Срез по чтению исходников 2026-10-06; в рамках подготовки плана тесты и миссии заново не запускались. Работа в соседних сессиях может менять код.

| Основа | Наблюдение в коде | Следующий шаг |
| --- | --- | --- |
| Чистое ядро и адаптеры | `backend/src/domain`, `application`, `adapters`; ROS/HTTP/LLM выделены | Сохранить направление зависимостей; выделять новые модули по ответственности, не по числу файлов |
| Миссия | `MissionController` координирует жизненный цикл, поиск, эксперименты, LLM и журнал | Постепенно вынести исследование и исполнение плана за небольшие интерфейсы; оставить единого владельца состояния прогона |
| Сценарии | `generate_easy_scenario`, `SUPPORTED_SCENARIOS = ("easy",)`; supervisor загружает `local_easy.json` | Ввести профили 3/1, 5/3, 7/4 и закрытый механизм событий |
| Стоимость грунта | `TerrainEstimator` накапливает дистанцию и расход по пространственным ячейкам | Добавить качество измерений, актуальность и обнаружение смены режима; старые данные не должны заглушать новое изменение |
| Гипотезы | `HypothesisBook`, повторный проезд и вывод предусмотрены | Подтвердить цикл в Gazebo; расширить на удешевление грунта и надёжность датчика |
| Планирование | `Planner.propose` возвращает одну подцель, текст миссии задан промптом | Ввести текст миссии и короткий план из нескольких подцелей с пересмотром после наблюдений |
| Сбор | Есть целевое число образцов, по умолчанию 3, и ограничения попыток | Не переносить константу easy в medium/hard; управлять сбором по выгоде, наблюдениям и запасу возврата |
| Грунт в среде | Судья моделирует только дополнительный расход | Проверить трактовку ТЗ и добавить измеримое замедление на стороне среды |
| Наблюдения | ROS различает отсутствие sample-сигнала и критических данных; штрафы сводятся к признаку `penalty_recent` | Сохранить различие критических/некритических отказов; передавать типизированные события для атрибуции опасности |
| Изоляция знаний | При проверке перед коммитом mount backend сужен до публичной карты `simulation/judge/data` | Проверять отсутствие закрытых конфигураций/журналов при расширении сценариев и образов |
| Панель | Есть отдельный frontend и HTTP-контракт MVP | Добавить план, качество модели, эксперимент и причину перепланирования; переиспользовать текущий интерфейс |

## Порядок достижения цели

1. **Надёжный базовый прогон:** сбор, возврат, остановка, сброс и повтор; зафиксировать исходные результаты.
2. **Полная среда:** три профиля сценариев, замедление, скрытые события и независимая проверка судьи.
3. **Научный агент:** прогноз → проверка → измерение → вывод → изменение следующего решения.
4. **Адаптация:** отдельно проверить смену грунта, новую опасность и отказ датчика, затем совместный hard.
5. **Конкурсная приёмка:** серия незнакомых сценариев, сравнение с базовым алгоритмом, реальные вызовы LLM, доказательный пятиминутный показ.
6. **Все бонусные возможности:** кастомные скиллы и логи процесса, SLAM и координация двух роботов в отдельных проверяемых конфигурациях, затем совместный режим двух роботов со SLAM. Это обязательные этапы цели команды.

Пункты 2 и 3 разрабатываются параллельно после фиксации интерфейсов. Пункт 4 зависит от обоих. Полный план не требует переписывать проект или менять стек: Python/ROS/FastAPI, TypeScript/React и Docker остаются.
