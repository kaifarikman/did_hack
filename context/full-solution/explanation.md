# Полное решение простыми словами

Сохранено по запросу пользователя 2026-10-06. Это объяснение целевой архитектуры и плана; оно не означает, что все перечисленные возможности уже реализованы.

Весь кейс технически можно реализовать на выбранном стеке: Python/ROS/FastAPI, TypeScript/React и Docker. Основа уже есть. Качество подтверждаем измерениями и прогонами, особенно для адаптации, SLAM и взаимодействия двух роботов. Совместимость с точными правилами организаторов проверяется отдельно: часть правил в ТЗ не раскрыта.

Пользователь выбрал полный объём без сокращений из-за времени: основной кейс, все сценарии, SLAM, два робота, научный журнал, кастомные скиллы и доказательства разработки.

## Главная идея архитектуры

Разделяем фактический мир, наблюдения и знания агента.

Симуляция знает, где лежат образцы и когда изменится грунт. Агент получает только разрешённые измерения, строит собственную модель и может ошибаться. Его задача — обнаруживать эти ошибки и исправлять модель. Это исследовательская часть проекта.

| Часть | За что отвечает |
| --- | --- |
| Исследование | Оценки грунта, гипотезы, эксперименты, обнаружение изменений |
| Планирование | Выбор целей и последовательности действий через LLM или резервный алгоритм |
| Навигация | Достижимый маршрут, стоимость, препятствия |
| Исполнение | Проверка энергии, выполнение действий, остановка, возврат |
| Журнал и панель | Измерения, выводы и понятное объяснение решений |

LLM предлагает план, исполнитель проверяет каждый шаг. Подтверждение гипотезы рассчитывается по измерениям; модель может объяснить результат.

Пример: робот ожидал дешёвый проход, обнаружил повышенный расход, запланировал проверочную поездку, подтвердил изменение и выбрал другой маршрут с запасом энергии на возврат. В журнале остаются прогноз, действие, измерения и причина решения.

## Порядок реализации

1. **Надёжный одиночный робот.** Сбор, возврат, повторный запуск, остановка и обработка сбоев.
2. **Полная среда.** Easy/medium/hard, измеримое замедление грунта, скрытые изменения и проверенный судья.
3. **Настоящее исследование.** Прогноз до поездки → проверочное действие → новые измерения → вывод → изменение решения.
4. **Адаптация.** Подорожавший и подешевевший грунт, новая опасность, шумящий или отказавший датчик.
5. **SLAM и команда роботов.** Сначала проверяем отдельно, затем запускаем двух роботов со SLAM, общими знаниями и распределением задач.
6. **Доказательство результата.** Сравнение стратегий, контрольные сценарии, кастомные скиллы, история разработки и демонстрация.

Особенно внимательно проверяем перенос измерений после коррекции карты SLAM, одновременный сбор одного образца, потерю партнёра, устаревший ответ LLM и сохранение энергии на возврат.

## Два потока разработки

- **A:** симуляция, ROS, судья, грунты, события, SLAM.
- **B:** агент, исследования, адаптация, координация и панель.

Интерфейсы между ними согласуются заранее. Параллельная разработка не отменяет совместную проверку в настоящем Gazebo.

## Как докажем готовность

Четыре режима: один/два робота × готовая карта/SLAM. Каждый проходит easy/medium/hard. Целевая финальная серия — минимум 120 прогонов, плюс отдельные проверки отказов и сравнение с базовыми алгоритмами. Это план испытаний, а не уже достигнутый результат.

«Всё покрыто» означает, что для каждого требования есть воспроизводимое свидетельство. Наличие файла, класса, красивой панели или одной успешной поездки недостаточно для доказательства всего решения. Глобальный оптимум сбора при неизвестных образцах и успех при любой физической поломке заранее не обещаем.
