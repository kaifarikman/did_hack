Реальный ход работы; решения, отказы и исправления, а не пересказ результата. Применения скилла `ros-check` помечены.

## 2026-10-07

1. **Старт.** Прочитаны `context/README.md`, `agent-a.md`, `two-agents.md`. В основном checkout лежали незакоммиченные результаты параллельной приёмки MVP (ROS-shutdown, протокол, артефакты). Создан worktree `agent-a`; результаты перенесены копированием и закоммичены тремя отдельными коммитами. Риск: при коммите тех же файлов в `main` возникнут дубли — оставлено на решение пользователя.
2. **Изоляция стеков.** В Compose зашиты ROS_DOMAIN_ID=7 и GZ_PARTITION=did. Параметризовал через переменные с прежними значениями по умолчанию, добавил `infra/stack-b.env.example`. Первая попытка правки `sed` упала на BSD-синтаксисе (macOS) — переписал на Python. Проверка: `docker compose config` для обоих наборов.
3. **Профили сценариев.** Генератор расширен до 3/1, 5/3, 7/4. Первая версия проверки разрешимости — только достижимость; добавлен расчёт кратчайшего пути (Dijkstra по 8-связной сетке) и правило «путь туда-обратно ≤ 50% батареи». Потоки случайности разделены по назначению (`"{seed}:zones"`, `":samples"`, `":events"`). Побочный эффект: раскладка easy для прежних seed изменилась относительно ранних прогонов MVP — старые артефакты нельзя сопоставлять с новыми seed по координатам.
4. **Скрытые события hard.** Смена зоны грунта, опасная зона, три вида отказа датчика. Ошибка в собственном тесте: считал штраф опасной зоны после первого входа (штраф уже списан) — исправил порядок замеров.
5. **Живая проверка hard** (`ros-check`, шаги 2.1–2.3). Первый `ros2 topic echo` не нашёл `/did/sample_sensor` («does not appear to be published yet») — это задержка discovery, а не дефект; повтор с явным типом сообщения показал значение 0.56.
6. **Замедление грунта.** Выбрано масштабирование `linear.x` в страже скорости, зоны передаются файлом внутри контейнера simulation (не ROS-топик, чтобы не раскрыть истину агенту). Альтернатива «трение в Gazebo» отвергнута: нужна воспроизводимая и измеримая модель, а не подбор физических параметров. Проба: 0.275 м в зоне против 0.548 м вне (0.501). Судью для пробы пришлось остановить, иначе он каждые 0.2 с перезаписывал состояние.
7. **Физическая поза.** Проверил наличие `gz.transport13`: без `source setup.bash` модуль не находится (ложная тревога «нет привязок»). Подписка на `/world/default/pose/info`, сущность `burger`. Живая проверка: расход 0.541 при проезде 0.545 м, в логе нет отката на odom. Коллизии по-прежнему по лидару — честно записано как частично.
8. **Утечки.** Первая версия `leak_check.py` дала ложное срабатывание (`engine.py` совпал с хвостом `appengine.py`) — перешёл на сравнение имени файла целиком, добавил регрессионный тест. Для имени образа проекта `agent-a` образа нет: скрипт теперь сообщает «не проверен» (код 2), а не падает.
9. **Ограничение среды.** Политика Bash отклоняет составные команды в worktree-сессии (heredoc, `docker exec … bash -c`, `cd` перед `git`); работал через файлы и отдельные команды. Это замедлило, но не изменило результаты.
10. **Скилл `ros-check`** оформлен по этому опыту (`.agents/skills/ros-check/SKILL.md`).
