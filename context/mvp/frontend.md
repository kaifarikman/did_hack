# Агент B: панель наблюдения MVP

Статус (2026-10-06): FE-01–FE-05 реализованы и проверены автотестами; FE-03 закрыт визуальным прогоном; FE-06 выполнен (см. `frontend/README.md`); FE-07 не начат. Это рабочий план команды. Агент B может выполнить FE-01–FE-06 независимо от backend; FE-07 требует работающей среды агента A.

Сначала прочитать [architecture.md](architecture.md), [interface.md](interface.md) и общие [примеры](examples/). Контракт — источник истины для полей, единиц, команд и переходов. Владелец B: `frontend/` и этот файл. Compose, backend, симуляция и общий контракт принадлежат другим исполнителям.

## Пул задач

### FE-01 — Основа приложения и два источника состояния

- [x] Выполнено (автотесты; визуально не проверено).
- **Зависимости:** общий контракт и его примеры.
- **Результат:** React/TypeScript/Vite, lock-файл, слои `domain`, `application`, `adapters`, `ui`; порт доступа к миссии, HTTP- и fixture-адаптеры, сборка зависимостей в точке запуска. Правила представления — чистые функции, React получает модель через application. Порты вводить для реальных заменяемых зависимостей, а не для каждого компонента.
- **Приёмка:** явный fixture-режим запускается без backend и постоянно показывает «Демо-данные». Общие JSON-примеры используются как исходные снимки; дополнительные последовательности живут в `frontend/`. Live-режим обращается к относительному `/api/v1`, при ошибке показывает её пользователю. Ядро не импортирует React, HTTP, DOM или browser storage. Неизвестные поля допускаются, некорректные обязательные значения дают понятную ошибку.
- **Проверка:** одна проверка поведения порта для обоих адаптеров на общих примерах, обработка `null` и некорректного снимка; сборка и проверка типов.

### FE-02 — Обновления состояния и восстановление связи

- [x] Выполнено (автотесты; визуально не проверено).
- **Зависимости:** FE-01.
- **Результат:** lifecycle опроса по контракту, контроль устаревания, загрузка карты при смене `map_id`, изоляция запросов по поколению соединения и текущему `run_id`.
- **Приёмка:** ответы с меньшей `revision` не откатывают состояние. Смена прогона очищает предыдущие путь, журнал и выбранную гипотезу; запоздавший ответ старого запроса их не возвращает. Пауза часов симуляции не означает потерю связи. После 3 секунд без успешного ответа последние значения помечаются устаревшими; восстановление возобновляет обновления. Размонтирование освобождает таймеры и запросы. Несовпадение версии карты видно до загрузки подходящей карты.
- **Проверка:** управляемые часы и отложенные ответы: отсутствие параллельных запросов состояния, снижение revision, поздний ответ после нового прогона, ошибка → stale → reconnect, пауза симуляции, cleanup.

### FE-03 — Карта и наблюдения робота

- [x] Выполнено: геометрия покрыта тестами; визуальный прогон в headless Chrome (карта, робот, путь, база, сбор, оценка грунта, ресайз) пройден 2026-10-06.
- **Зависимости:** FE-01, FE-02.
- **Результат:** Canvas или SVG с occupancy-картой, роботом и направлением движения, базой, текущей целью, планируемым путём, траекторией, подтверждёнными сборами и оценками грунта.
- **Приёмка:** геометрия учитывает resolution, смещение и поворот origin, центры клеток и экранную ось Y по контракту. Слои имеют легенду; грунт подписан как оценка агента с confidence, скрытых образцов на карте нет. `null`-позиция не превращается в робота в начале координат. Карта помещается в доступную область при изменении размера окна.
- **Проверка:** чистое преобразование координат на асимметричной карте с ненулевым origin и поворотом; визуальный браузерный прогон с путём, базой и препятствиями, проверка ресайза.

### FE-04 — Панель миссии и команды

- [x] Выполнено (автотесты; визуально не проверено).
- **Зависимости:** FE-02.
- **Результат:** статус, время симуляции, батарея в условных единицах, оценка энергии возврата, сигнал образца, число сборов, текущая цель и причина решения; видимые метки `local/official` и `llm/fallback`, состояние готовности среды. Start с seed easy-прогона и Stop.
- **Приёмка:** отсутствие измерения показано как отсутствие данных; батарея не подписана процентами. Start доступен после готовности и согласования текущего состояния, Stop отправляет прерывание. HTTP 202 показывает ожидание фактического перехода; успех рисуется только по `completed`. Двойной клик не создаёт второе намерение. Повтор после таймаута сохраняет `request_id` логической команды. После разрыва связи сначала сверяется `/state`; старые команды автоматически не воспроизводятся. Ошибки 409/422/503 дают читаемое сообщение и возможность восстановиться.
- **Проверка:** сценарии double click, 202 с последующим переходом, неизвестный итог команды после таймаута, ошибка среды, reconnect; `stopped` и `failed` визуально отличаются от успешного завершения.

### FE-05 — Журнал исследования и полный экспорт

- [x] Выполнено (автотесты; визуально не проверено).
- **Зависимости:** FE-02, FE-04.
- **Результат:** последовательный журнал с фильтром по типу события, раскрытием detail и просмотром цепочки гипотезы по `hypothesis_id`: ожидание, эксперимент, наблюдение, вывод. Экспорт текущего прогона в JSON с `run_id` и всеми записями.
- **Приёмка:** пагинация продолжает чтение через `next_sequence` и `has_more`; дубликаты по `(run_id, sequence)` удаляются. Незавершённая гипотеза отображается без придуманного вывода. Экспорт читает все страницы независимо от экранного фильтра; при ошибке не выдаёт частичный файл за полный. При экспорте активного прогона чтение заканчивается на первой странице с `has_more: false`; её `next_sequence` сохраняется в файле как верхняя граница выгрузки. Новые события после неё относятся к следующему экспорту; атомарный снимок на момент нажатия кнопки не обещается. Смена прогона не смешивает записи и сообщает об отмене незавершённой выгрузки.
- **Проверка:** журнал больше двух страниц, повтор страницы, пустая страница, сбой в середине экспорта, приход новых записей во время выгрузки и смена `run_id`; содержимое файла совпадает с полным журналом до зафиксированной границы.

### FE-06 — Контейнер и автономная приёмка

- [x] Выполнено: Dockerfile, README, smoke на 8080, браузерный прогон всех демо-сценариев, экспорта и ручной остановки пройдены. Ограничение: полная навигация только с клавиатуры не проверена.
- **Зависимости:** FE-03, FE-04, FE-05.
- **Результат:** `frontend/Dockerfile`, документированные запуск, fixture/live-режимы и проверки в `frontend/README.md`. Production-сервер слушает `0.0.0.0:8080`, проксирует `/api/v1` через задаваемый при запуске контейнера `BACKEND_URL`; стандартное значение для Compose — `http://backend:8000`. Dev-прокси использует ту же переменную. LLM-секретов во frontend нет.
- **Приёмка:** агент A получает точные build context, порт, переменные и команды для Compose. Fixture-контейнер работает без backend; live-сборка работает через тот же origin браузера. Браузер проверен на обычном ноутбучном и узком окне; кнопки доступны с клавиатуры, подписи различимы, ошибки видны.
- **Проверка:** сборка контейнера и smoke на 8080; fixture-сценарии успешной миссии, отказа LLM, разрыва связи, ошибки и ручной остановки. Сохранить команды и результаты проверки в README, не выдавая fixture за доказательство симуляции.

### FE-07 — Совместная проверка живой миссии

- [ ] Выполнено.
- **Зависимости:** FE-06 и готовый backend с Gazebo, ROS, судьями/адаптерами и HTTP API агента A.
- **Результат:** исправления только frontend по результатам общей приёмки, запись проверенных сценариев и оставшихся ограничений.
- **Приёмка:** панель подключена к реальной симуляции; видны движение, подтверждённый сбор, возврат и завершение. Повторный запуск очищает прошлое состояние. Stop приводит к фактической остановке по backend. Отключение и восстановление backend корректно отражаются в панели. Экспорт совпадает с журналом проверенного прогона. Режим судьи и планировщика отражает реальность.
- **Проверка:** совместный браузерный smoke с агентом A, сверка `run_id` и нескольких событий с журналом backend. Любой неисполненный критерий остаётся незакрытым.
