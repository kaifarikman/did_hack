## Остановка и восстановление

Предыдущая интеграционная проверка документирована в [BE-10](backend.md):
отключение backend сохраняет последние значения, показывает «Данные устарели»,
блокирует Start/Stop; после восстановления обновления возобновляются сами
([кадр потери связи](../../artifacts/panel-backend-lost.jpg)).
Другой исполнитель проверил `docker compose down` → `up -d` и готовность сервисов.
Это отдельные свидетельства, не результат непрерывной пары новых миссий.

При выключении обнаружена воспроизводимая ошибка: ROS закрывал контекст,
после чего приложение пыталось опубликовать остановку (`publisher's context is invalid`).
Теперь обработка SIGTERM остаётся у сервера приложения; штатный shutdown сначала
публикует нулевую скорость, завершает executor, освобождает узел и закрывает ROS.
Повторный shutdown и уже закрытый контекст обработаны явно.

## Проверки кода

Три регрессионных теста на настоящем ROS: закрытый контекст, повторный shutdown,
владение SIGTERM приложением. До исправления два теста падали; после исправления — 3 passed.

```sh
docker compose exec -T -e ROS_DOMAIN_ID=79 backend bash -c \
  'source /opt/ros/jazzy/setup.bash && python3 -m pytest tests/test_ros_lifecycle.py -q'

docker run --rm -e ROS_DOMAIN_ID=79 -v "$PWD:/workspace:ro" \
  -w /workspace/backend --entrypoint bash did_hack-backend -c \
  'source /opt/ros/jazzy/setup.bash && python3 -m pytest tests -q'
```

Полный backend: **86 passed**. В обычном production-контейнере полный набор первоначально дал
5 ошибок отсутствующих файлов: общие контрактные примеры и карта находятся вне его build context.
Команда выше подключает репозиторий только для тестового процесса и не меняет доступ production-backend.
Read-only mount вызывает предупреждения записи pytest cache; также есть предупреждение зависимости
Starlette/httpx. В полном запуске ROS напечатал одно асинхронное сообщение об уничтоженном объекте;
отдельный повтор трёх lifecycle-тестов завершился без него. Код завершения полного набора — 0.

Ранее пройдены 40 тестов судьи, 75 тестов frontend и сборка UI
([ревью](../review-2026-10-06.md)); их код в этой проверке не менялся.

## Границы результата

- Повтор одного seed не означает идентичной траектории: ответы LLM и физическое выполнение недетерминированы.
- Два успешных повтора — минимальная приёмка, а не статистическая гарантия надёжности.
- На карте много неизвестного пространства, подписи оценок местами перекрываются.
- После завершения панель сохраняет последнюю подцель возврата; статус миссии при этом терминальный.
- Вместо видео сохранены последовательности состояний и кадры живой панели.
