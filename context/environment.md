## Проверка LLM — 2026-10-06

Пользователь заполнил корневой `.env`. Он исключён из Git и Docker build context; значения ключа в документацию не копируются. `LLM_ENDPOINT` исправлен с базового `/v1` на полный `/v1/chat/completions`, требуемый текущим HTTP-клиентом.

Через `OpenAiCompatiblePlanner` выполнен реальный запрос с синтетическим состоянием миссии и моделью `gpt-5.5`: за 5,77 с получена подцель `approach`, ответ прошёл разбор схемы, цель совпала с разрешённым кандидатом, объяснение присутствует. Это проверка доступа и формата ответа, а не выполнение миссии в Gazebo.

При проверке `.env` загружался явно в тестовый процесс. Перед интеграцией нужно обеспечить передачу переменных в backend-контейнер: наличие корневого `.env` само по себе не передаёт их процессу приложения.
