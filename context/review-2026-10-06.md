# Проверка MVP перед коммитом

Дата: 2026-10-06. Основание: пользователь сообщил о завершении изменений, попросил проверить их, сохранить объяснение в Markdown и при успешной проверке сделать commit/push.

## Объём и вывод

Проверяется текущий MVP и документы полного плана. Реализация полного плана F01–F22 не завершена: backend допускает только easy, LLM выдаёт одну подцель, генератор создаёт easy, грунт увеличивает расход без физического замедления. SLAM, два робота и полноценный hard отсутствуют. Эти возможности остаются задачами, а не подтверждённым результатом.

Текущий MVP имеет сохранённые свидетельства реальных успешных миссий и научного цикла. Его можно фиксировать как промежуточную версию с указанными ограничениями. Полная приёмка MVP также ещё не закрыта: FE-07, отдельные проверки потери backend глазами UI и выключения стека остаются открытыми; отметка BE-10 скорректирована.

## Что проверено заново

- Backend: `cd backend && python3 -m pytest tests -q` — 80 тестов до исправлений, 83 после них.
- Судья: `docker compose exec -T simulation python3 -m pytest /workspace/simulation/judge/tests -q` — 40 тестов. На корневом системном Python pytest не установлен, поэтому использована среда контейнера.
- Frontend: `cd frontend && npm test && npm run build` — 75 тестов, проверка типов и production-сборка успешны.
- `docker compose config --quiet` — конфигурация корректна.
- Read-only smoke через панельный прокси: health сообщает ready, ROS подключён, LLM настроена; состояние на момент проверки idle. Это не новый автономный прогон.
- После пересборки backend выполнен короткий живой start → движение → stop на easy seed 2. Статус `stopped`, ошибок нет. Независимая ROS-проверка после остановки подтвердила нулевые команды и неподвижную позу; результат в `artifacts/review-start-stop.json`. Это не полная миссия со сбором/возвратом.
- В запущенном backend проверено, что из каталога судьи доступны только `data/map.yaml` и `data/map.pgm`; конфигурация и код судьи отсутствуют.
- Проверены исходники и сохранённые JSON-артефакты; новая полная миссия в ходе ревью не запускалась.

## Обнаруженные и исправленные проблемы

1. **Обход лимитов сбора решением LLM.** `MissionController._verdict` не проверял число неудачных попыток, а `validate_subgoal` принимал любой присутствующий сигнал. Повторяемая подцель collect могла расходовать батарею на ложные сборы сверх ограничений резервного алгоритма. Добавлены проверки общего/локального лимита и порога сигнала. Регрессионные тесты воспроизводили отказ до исправления и проходят после.
2. **Запас возврата не имел приоритета при выборе новой подцели на месте.** Проверка выполнялась во время движения, а при остановке агент мог обращаться к LLM и принимать collect при низкой батарее. В `_decide` возврат теперь выбирается до планировщика и экспериментов; отдельный тест проверяет отсутствие вызова LLM.
3. **Backend имел доступ к файлам среды.** Compose монтировал весь `simulation`, хотя нужна только публичная карта. Mount сужен до `simulation/judge/data`; путь карты сохранён. Это исключает текущую конфигурацию судьи из mount агента, но не заменяет будущий аудит скрытых данных.
4. **Документация противоречила артефактам.** Устаревший текст «реализация не начата» исправлен, неподтверждённая полная приёмка не выдаётся за завершённую. Объяснение архитектуры сохранено в [full-solution/explanation.md](full-solution/explanation.md).

Локальные секреты, `.DS_Store`, виртуальные среды, зависимости и кеши исключаются из публикации. Коммит должен обозначать MVP и план; полный кейс не объявляется реализованным.

Проверка подготовленного содержимого не обнаружила значений локальных секретов, типичных токенов или приватных ключей. Проверены ссылки контекста и `git diff --cached --check`. У текстовых артефактов нормализованы окончания строк, PGM обозначен как двоичный файл.

## Оставшиеся ограничения

- После новых проверок допуска подцелей нужно повторить полную физическую миссию: старые артефакты не подтверждают новый исход.
- Полная UI-приёмка FE-07 не завершена; существующие скриншоты не заменяют весь набор её сценариев.
- Запас батареи в одном сохранённом прогоне составляет всего 1,41 из 60. Надёжность энергетической модели требует серии испытаний, предусмотренной полным планом.
- Формулы локального судьи и его условия не подтверждают совместимость с неизвестным официальным судьёй.
- Ревью затронуло критические пути управления и интеграции; оно не является исчерпывающим доказательством отсутствия ошибок во всём новом репозитории.
